# ポートフォリオ・ヘルスチェック

保有銘柄の売買記録を管理し、テクニカル×ファンダメンタルズの2軸で
定期的なヘルスチェックを行うスキル。

## 対象ユーザー

投資初心者の「ふゆさん」。アラートや判定結果は専門用語を避けて
「つまりどういうこと？」レベルで伝える。

---

## データ管理

### 保存先
GitHubリポジトリ `bi-al1/stock-dashboard` の `data/portfolio.json`

読み書きは全て **Render API（`https://stock-dashboard-rif1.onrender.com`）経由** で行う。
Claudeが直接JSONを編集したりgit pushしたりする必要はない。

## コマンド

### 1. 売買記録（buy / sell）

**トリガー例：**
- 「7203を100株、2500円で買った」
- 「トヨタを50株売った、3000円で」
- ウォッチリストから「これ買った」と伝えられた場合

**処理（買い）：**
1. Render API `POST /api/portfolio/buy` を呼び出す
2. ウォッチリストから移行の場合、`DELETE /api/watchlist/{code}` も呼び出す
3. 「✅ {企業名} {株数}株を{価格}円で買い記録しました」と返答

```bash
curl -X POST https://stock-dashboard-rif1.onrender.com/api/portfolio/buy \
  -H "Content-Type: application/json" \
  -d '{"code":"7203","name":"トヨタ自動車","shares":100,"price":2500}'
```

**処理（売り）：**
1. Render API `POST /api/portfolio/sell` を呼び出す
2. 「✅ {企業名} {株数}株を{価格}円で売り記録しました」と返答

```bash
curl -X POST https://stock-dashboard-rif1.onrender.com/api/portfolio/sell \
  -H "Content-Type: application/json" \
  -d '{"code":"7203","shares":50,"price":3000}'
```

### 2. スナップショット（一覧表示）

**トリガー例：**
- 「ポートフォリオを見せて」
- 「持ってる銘柄一覧」
- 「損益はどう？」

**処理：**
1. Render API `GET /api/portfolio` を呼び出す（現在株価付きで返ってくる）
2. 以下を一覧表示：
   - 銘柄コード・企業名
   - 保有株数・平均取得単価
   - 現在株価・評価額
   - 損益額・損益率（%）
3. ポートフォリオ全体の合計評価額・合計損益も表示

```bash
curl https://stock-dashboard-rif1.onrender.com/api/portfolio
```

### 3. ヘルスチェック（定期監視の本体）

**トリガー例：**
- 「ヘルスチェックして」
- 「持ってる銘柄、大丈夫？」
- 「ポートフォリオの健康診断」

**処理：**
1. Render API `GET /api/healthcheck` を呼び出す
2. 全保有銘柄のテクニカル×ファンダ判定結果が返ってくる
3. Claudeがアラート内容を初心者向けに解説して表示

```bash
curl https://stock-dashboard-rif1.onrender.com/api/healthcheck
```

#### アラート判定基準（3段階）

**🟡 早期警告（注視）**
- テクニカル条件：SMA50を下回った / RSIが30以下に急落
- ファンダ条件：なし（テクニカルのみで発動）
- 意味：「ちょっと株価の動きが怪しいけど、まだ慌てなくていい」
- アクション：様子を見る

**🟠 注意（一部利確を検討）**
- テクニカル条件：SMA50がSMA200に接近（差が5%以内）
- ファンダ条件：変化スコアの4指標のうち1つが悪化（前回比）
- 意味：「株価のトレンドが弱まってきて、業績にも少し陰りが見える」
- アクション：一部利確を検討

**🔴 撤退検討**
- テクニカル条件：デッドクロス（SMA50がSMA200を下抜け）
- ファンダ条件：変化スコアの4指標のうち複数が悪化
- 意味：「株価も業績も下向き。持ち続ける理由を見直したほうがいい」
- アクション：撤退を検討

**重要な設計判断：**
撤退シグナルにはテクニカル崩壊とファンダ悪化の**両方を要求する**。
デッドクロスしていてもファンダが良好なら「注意」止まり。
一時的な需給の崩れだけで売りシグナルを出すと過剰反応になるため。

#### 出力フォーマット

各銘柄について：
```
{企業名}（{コード}）
  アラート：🟡早期警告 / 🟠注意 / 🔴撤退検討 / ✅問題なし
  テクニカル：{SMAステータス、RSI、トレンド}
  つまり：{初心者向けの一文まとめ}
```

全銘柄のヘルスチェック後、サマリーを表示：
- 問題なし：N銘柄
- 注視：N銘柄（銘柄名を列挙）
- 注意：N銘柄（銘柄名を列挙）
- 撤退検討：N銘柄（銘柄名を列挙）

### 4. 推定利回り

**トリガー例：**
- 「ポートフォリオの利回りはどう？」
- 「持ってる銘柄の今後の予想」

**処理：**
`GET /api/healthcheck` で取得したfundamentalsデータをもとに、
ポートフォリオ全体のリターン見通しを集計して表示。

各銘柄：
- ROE・営業利益率・売上成長率の状況
- アラートレベルとの組み合わせで総合コメント

## ヘルスチェックの「つまり」解説

初心者向けに、各アラートの意味を必ず添える：

- **SMA50割れ** → 「最近の株価が、過去50日の平均を下回った。短期的に弱い」
- **SMA50がSMA200に接近** → 「短期トレンドと長期トレンドがぶつかりそう。転換点かも」
- **デッドクロス** → 「短期の平均が長期の平均を下回った。下降トレンドに入った可能性」
- **RSI 30以下** → 「売られすぎの状態。反発するかもしれないけど、下がり続ける可能性も」
- **ファンダ悪化** → 「会社の業績が前より悪くなってきている兆し」

## watchlistからの移行

ウォッチリストに登録されている銘柄について「買った」と伝えられた場合：
1. `POST /api/portfolio/buy` でポートフォリオに記録
2. `DELETE /api/watchlist/{code}` でウォッチリストから削除
3. 「✅ ウォッチリストから移動しました。{企業名}を{株数}株、ポートフォリオに記録しました」

## データ反映フロー（Webアプリ連携）

```
Claude
  ↓ Render API を呼び出す（curl / fetch）
Render FastAPI（https://stock-dashboard-rif1.onrender.com）
  ↓ GitHub Contents API を呼び出す
GitHub（bi-al1/stock-dashboard）の data/portfolio.json を更新・コミット
  ↓
ブラウザで「更新」ボタンを押すと最新データが反映される
```

**Claudeはgit pushを実行しない。** Render APIが自動的にGitHubを更新する。

## 技術仕様

- データ：`bi-al1/stock-dashboard` リポジトリの `data/portfolio.json`（GitHub管理）
- 株価取得・ヘルスチェック：Render FastAPI が yfinance で実行（`GET /api/healthcheck`）
- Webダッシュボード：`https://stock-dashboard-pi-navy.vercel.app`（Vercel）
- バックエンドAPI：`https://stock-dashboard-rif1.onrender.com`（Render）

---

## 注意事項

- このスキルは投資助言ではない。アラートはあくまで定量的な指標に基づく参考情報
- 売買の最終判断はユーザー自身が行うことを必ず伝える
- Renderは無料枠のためスリープあり。初回呼び出しは数秒かかる場合がある
- yfinanceが使えない場合、ヘルスチェックと推定利回りは実行不可（エラーメッセージを表示）
